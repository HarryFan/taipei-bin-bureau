# 🗑️ 台北桶報局

> 市政 debug松 #2「找回消失的垃圾桶」｜隊伍：同流 One Flow
>
> **線上試用：** 市民端 https://taipei-bin-bureau.vercel.app ・ 市府戰情 https://taipei-bin-bureau.vercel.app/#/admin ・ 3D 城市戰情室 https://taipei-bin-bureau.vercel.app/#/3d
>
> **介紹影片：** https://youtu.be/nh-yJZHnAwY （實際系統畫面版）・ 第一版情境短片 https://youtu.be/8s3M5DoNdEE

市民一鍵找到最近的垃圾桶、回報滿了或不見了；市府從同一份回報看見「垃圾桶沙漠」，並依填滿率安排清運。

工作清單與分工進度見 [TODO.md](TODO.md)；提交清單與 YouTube 影片腳本見 [docs/SUBMISSION.md](docs/SUBMISSION.md)。會議紀錄放在 [docs/meetings/](docs/meetings/)。市府處理流程與實作對照見 [docs/FLOW.md](docs/FLOW.md)。

**資料來源、數字單位與資料驅動的開發需求見 [docs/DATA_SOURCES.md](docs/DATA_SOURCES.md)，動工前請先讀第 0 節。**

## 技術棧

| 層 | 技術 | 說明 |
| --- | --- | --- |
| 前端框架 | Vue 3.5、TypeScript 5.9、Vite 7.3 | 單頁應用，`vue-tsc` 型別檢查 |
| 路由 | Vue Router 4（hash 模式） | `/` 市民端、`/admin` 市府戰情、`/bin/:id` 掃碼回報、`/qr` 列印貼紙；hash 模式部署到任何靜態主機都不用設定轉址 |
| 樣式 | Tailwind CSS 4.3 | 設計語彙「台灣道路指示牌 × 清潔隊垃圾車」，色彩定義在 `apps/web/src/style.css` 的 `@theme` |
| 地圖 | Leaflet 1.9（canvas 繪製） | 底圖以國土測繪中心為主、OpenStreetMap 備用，連不上或逾時 5 秒就自動換 |
| 動畫 | GSAP 3.15 | 市府戰情的數字滾動；垃圾車沿路線行駛用 `requestAnimationFrame` |
| QR Code | qrcode 1.5 | 產生貼紙；簽章與驗證目前在前端示意，正式版改由後端處理 |
| 字型 | Chiron GoRound TC、Barlow Semi Condensed | 以 @fontsource 打包在專案內，現場沒網路也能顯示 |
| 後端（暫用） | Node.js 22，零相依 HTTP 伺服器 | `apps/api/server.mjs`，資料存在記憶體；API 連不上時前端自動改用瀏覽器儲存 |
| 後端（正式） | ASP.NET Core Minimal API | 由 Pamis 實作，端點與暫用版相同，見 TODO.md |
| 資料管線 | Python 3（只用標準庫） | 產生模擬資料、轉換開放資料、計算缺口網格，輸出靜態 JSON 到 `apps/web/public/data` |
| 簡報 | 手寫 HTML + GSAP 3.12 | `docs/slides/`，`npm run slides` 用 Node 提供本機網址；3 分鐘提案版在 `/pitch.html` |
| 部署 | Vercel（`vercel.json`）或 GitHub Pages（`.github/workflows/deploy.yml`） | 兩者都會把簡報一起放在 `<網址>/slides/` |
| 專案管理 | npm workspaces（monorepo） | 根目錄一個 `npm install` 裝好全部 |

### 結構

```
apps/web     前端：市民端、市府戰情、掃碼回報、QR 列印頁
apps/api     暫用的 Node API（正式版由 Pamis 以 ASP.NET Core 實作，端點相同）
data         Python 資料管線：mock/ 模擬資料、scripts/ 轉換與模型
docs         資料來源指南、提交清單、團隊簡報
scripts      跨平台的 Node 輔助腳本（簡報伺服器、資料管線執行器）
```

前端只讀靜態 JSON 也能完整運作，API 掛掉 Demo 不受影響。

## 如何啟動專案

### 1. 準備環境（第一次才需要）

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| [Node.js](https://nodejs.org/) | 22 LTS 以上 | 前端、簡報、暫用 API |
| [Python](https://www.python.org/) | 3.9 以上 | 資料管線（只有要重建資料時才需要） |
| Git、[GitHub CLI](https://cli.github.com/) | — | 取得程式碼 |

> Windows 安裝 Python 時請勾選 **Add python.exe to PATH**。

### 2. 取得程式碼並安裝

```bash
gh repo clone HarryFan/taipei-bin-bureau
cd taipei-bin-bureau
npm install
```

### 3. 啟動前端

```bash
npm run dev
```

打開 http://localhost:5173

| 網址 | 畫面 | 適合 |
| --- | --- | --- |
| http://localhost:5173/ | 市民端：找最近的垃圾桶、回報 | 手機（電腦也能看，清單在左側） |
| http://localhost:5173/#/admin | 市府戰情：缺口熱區、清運調度、即時回報 | 電腦、投影 |

不用啟動後端也能完整操作：資料讀 `apps/web/public/data/` 的靜態檔，回報存在瀏覽器裡。

### 4. 用手機看

```bash
npm run dev -- --host
```

終端機會顯示一個區網網址（例如 `http://192.168.1.23:5173`），手機連同一個 Wi-Fi 打開即可。

> 手機透過區網的 http 連線**拿不到定位**，會改用台北車站示範。要測定位，請用部署後的 HTTPS 網址。

### 5. Demo：手機回報 → 大螢幕即時出現

- **沒有後端時**：同一個瀏覽器開兩個分頁，一個開市民端、一個開 `/#/admin`。在市民端按「這桶滿了」，儀表板 3 秒內會跳出來。
- **有後端時**：先啟動 API，再讓前端連過去，手機和大螢幕就能跨裝置同步。

```bash
npm run api                                           # 暫用的 Node API，http://localhost:8787
cp apps/web/.env.example apps/web/.env                # 內容是 VITE_API_URL=http://localhost:8787
npm run dev                                           # 重新啟動前端
```

儀表板左上角會顯示「即時連線」或「離線模式」。Demo 前可以按儀表板上的「清空」清掉測試回報（離線模式才有）。

### 6. 其他指令

```bash
npm run build        # 打包到 apps/web/dist，部署用
npm run slides       # 團隊簡報 http://localhost:4321（← → 翻頁、F 全螢幕、R 重播動畫）
npm run data:build   # 重建地圖資料（有 data/raw 用真實資料，否則用 data/mock）
npm run data:mock    # 重新產生模擬資料再建置
```

### 常見問題

- **地圖只有點，沒有底圖**：底圖從國土測繪中心線上載入（備用 OpenStreetMap），網路不通時會顯示「地圖底圖載入失敗，請檢查網路」。垃圾桶位置與功能不受影響。
- **`npm run data:build` 說找不到 Python**：安裝 Python 3.9 以上並加入 PATH，Windows 可以用 `py --version` 確認。
- **畫面上寫「模擬資料」**：垃圾桶點位已是真實開放資料，但人流、陳情等需求資料與填滿率仍是模擬，見 [docs/DATA_SOURCES.md](docs/DATA_SOURCES.md) 第 3 節。
- **port 被占用**：`npm run dev -- --port 5180` 換一個。

## 資料來源

### 前台目前用到的資料：部分真實、部分模擬

前台只讀 `apps/web/public/data/` 的靜態 JSON（由 `npm run data:build` 產生），各檔的真假如下：

| 前台畫面 | 資料檔 | 來源 | 真實／模擬 |
| --- | --- | --- | --- |
| 地圖上 661 個垃圾桶的位置、行政區、地址 | `bins.json` | 環保局「行人專用清潔箱總表」開放資料，repo 內附 UTF-8 版 `data/open/121355-pedestrian-bins.csv`（2026-10 下載） | **真實** |
| 景點商圈周邊熱點 | `hotspots.json` | 環保局「行人專用清潔箱總表（景點商圈周邊 130 點）」，repo 內附 `data/open/hotspot-bins-130.csv` | **真實** |
| 頂欄「官方統計 806 組」 | `official_counts.json` | 環保局新聞稿（2026-08-10，2026 年 6 月數字） | **真實** |
| 每個桶的填滿程度、幾天前有人確認（待清運數、超過 14 天未確認數） | `fill_levels.json` | `data/scripts/simulate_fill.py` 以固定亂數產生，代替尚不存在的感測與巡查紀錄 | **模擬** |
| 缺口熱區、網格分數、候選新設點、各區缺口排名 | `grid.json` | 垃圾桶位置為真實資料，但人流需求點（捷運、公車、陳情、商圈）取自 `data/mock/demand_points.mock.csv` | **模擬**（需求端為模擬，算出的缺口僅供示意） |
| 市民回報、派車、處理紀錄 | 瀏覽器 localStorage 或 API | Demo 時現場操作產生 | 現場產生，非政府資料 |

`apps/web/public/data/meta.json` 也記錄了這件事：`bins.kind = real`、`demand.kind = mock`。

換成真實資料的方法：

- **缺口熱區**：把捷運進出量、公車站、陳情等開放資料各自轉成 `lat,lng,source,value` 格式，存成 `data/interim/demand_points.csv`，再執行 `npm run data:build`，缺口與候選新設點就會改用真實資料計算。
- **填滿率與確認紀錄**：環保局目前沒有公開感測或巡查資料，需等試辦期間由市民回報累積，或由局處提供。
- **垃圾桶點位更新**：下載新版 CSV，轉成 UTF-8 存成 `data/raw/bins.csv`（不進版控），執行 `npm run data:build` 即會優先採用。

## 掃碼巡桶與綠點（Demo 為示意）

- 每個垃圾桶貼 QR Code，掃了直接開到那一桶的回報頁（`/#/bin/<編號>?s=<簽章>`），不用下載 App。
- 列印 Demo 用貼紙：打開 `/#/qr`（市府戰情右上角「列印 QR」），最後一張是故意做壞的假貼紙，掃了會顯示驗證失敗。
- 「巡桶任務」依資料價值排序：很久沒人確認的桶、疑似沒有垃圾桶的地方。
- 綠點規則：掃碼回報 +5，超過 14 天沒人確認的桶再 +5，在沒有垃圾桶處回報 +3，每天上限 30。
- 防弊三原則：**回報什麼狀態都拿一樣的點數**（沒有說謊的誘因）、同一桶一天只算一次且點數先列為待確認、**丟垃圾不給點**（只獎勵檢查與回報）。
- Demo 版點數只存在瀏覽器，QR 簽章在前端計算，都只是示意。正式版要用台北通實名登入、後端簽章與驗證，並可接環保集點綠點。

### 經費：西門町 100 天試辦

試辦場域西門町商圈，50 至 100 個清潔箱點位，**提案預算上限新臺幣 50 萬元**；合作單位為環保局、萬華區清潔隊、資訊局、萬華區公所、西門町商圈組織與商家、學校與公益團體。

| 項目 | 估算方式 | 金額 |
| --- | --- | --- |
| QR Code 耐候貼紙 | 以萬華區 77 組 × 每組 2 座 = 154 張，另預留備品與汰換 | 依廠商報價 |
| 市民回報獎勵 | 接環保集點：77 組 × 每週 2 次 × 每次 1 元 × 52 週 | 全年約 8,008 元（示意） |
| 系統開發與維運 | 優先沿用臺北通、既有陳情系統與開放資料平台 | 由資訊局會同環保局估算 |
| 智慧感測器（選配） | 不一開始全面安裝，先在高滿溢點小規模測試、與市民回報比較 | 依測試結果 |

### 推廣計畫

- **QR Code 隨掃隨報**：清潔箱就是服務入口，回報後可以查處理進度。
- **臺北通與環保集點**：推播與綠點獎勵，以有效回報為原則，避免重複或不實回報。
- **交通場站與人潮密集區優先**：捷運站、公車站、商圈、觀光景點。
- **里辦公處與第一線清潔隊**：說明會與操作訓練，說明回報如何影響清運與會勘。
- **學校、社區與公益組織**：舉辦「巡桶日」，協助核對清潔箱位置與回報。
- **公開戰情儀表板**：公開案件數、處理進度、改善完成率與增設成果（本專案已有 `/#/status` 處理成績單）。
