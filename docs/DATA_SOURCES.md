## 0. 先讀這段：數字與單位

臺北市行人垃圾桶的數字常被誤用，主因是單位混用。官方文件裡「個、處、組、座」都出現過，開放資料又是以「點位」為單位。

| 單位 | 意思 | 何時出現 |
| --- | --- | --- |
| **組** | 一個設置點，現行款式是一般垃圾 + 資源回收兩座 | 2016 年換裝後的主要說法；主計處 105 年後的數字等同組數 |
| **座** | 單一箱體。換裝後 1 組 = 2 座 | 局長答詢、新聞稿 |
| **處** | 設置點，換裝後約等於組 | 107 年局長答詢 |
| **個** | 主計處報表的欄位單位，沒有正式定義 | 主計處、口頭答詢，常與組混用 |
| **點位（筆）** | 開放資料的一筆座標。同一地點可能拆成多筆，**不能加總成組數** | 開放資料 121355 |

### 可以直接引用的數字

| 說法 | 數字 | 來源 |
| --- | --- | --- |
| 目前數量 | **115 年（2026）6 月 806 組（1,612 座）** | 環保局新聞稿 2026-08-10；苗博雅議員質詢簡報 |
| 與 107 年比 | 107 年（2018）7 月 2,004 處、4,008 座 → 現在約剩 **四成** | 議會公報第 112 卷第 10 期 |
| 與 97 年比 | 97 年（2008）底 3,484 設置點 → 以設置點計約剩 **23%** | 主計處 TSIS |
| 開放資料點位 | 2026-10-21 版 **661 筆**，**北投區 0 筆** | data.gov.tw 121355 |
| 主計處 2023 年中 | 112 年 6 月底 1,984 個（＝組的量級） | 主計處市政統計週報第 1246 號 |

### 不要這樣用

- ❌「從近 3,000 組減到 800 組」：3,000 是舊款單箱時期的設置點，與現在的「組」不同單位。
- ❌「106 年 4,018 → 現在 806，剩五分之一」：4,018 較可能是座數。
- ❌ 用開放資料筆數加總當作全市組數，或把北投區 0 筆說成「北投沒有垃圾桶」。
- ✅ 一律寫出單位與基準年，例如「115 年 6 月 806 組，比 107 年 7 月的 2,004 處少了約六成」。

> 詳細的歷年對照與推論過程見 [臺北行人專用清潔箱數量整理](https://data.bin.ianwu.net/)，本節數字皆引自該報告，報告已對照主計處 TSIS 與議會公報原文。

## 1. 問題脈絡：為什麼垃圾桶只減不增

這段決定了產品要解決什麼，請前後端都讀。

- 2022-08-24《行人專用清潔箱設置管理作業程序》停止適用後，垃圾桶的增減改由**現場會勘**決定，參與者是**里長與清潔隊**。
- 會勘結果**必須里長同意**。里長代表居民，清潔隊要承擔清運，垃圾桶對居民是厭惡設施。
- **最需要垃圾桶的是路過的行人，但行人流動性高，會勘時沒有人代表他們。** 結構上容易減、難以增。
- 2023 年副市長曾表示評估恢復，市長也引用研考會調查「超過七成市民希望增設」，但之後數量仍持續減少。

**對產品的意義**：市民端的每一筆回報（滿了、找不到、這裡需要一個）都是**行人在會勘桌上缺席的聲音**。市府端要能把這些回報依地點彙整，成為會勘時的佐證資料。這是我們和一般「找垃圾桶 App」最大的不同。

## 3. 資料怎麼驅動前後端

### 3.1 資料 → 功能對照

| 功能 | 依據資料 | 負責 | 現況 |
| --- | --- | --- | --- |
| 地圖上的垃圾桶、找最近 | 121355 點位 | 資料 → 前端 | **真實資料**（`data/open/`，661 筆） |
| 全市官方總數、歷年變化 | 145763 主計處、新聞稿 | 資料 → 前端 | 未做 |
| 缺口熱區、建議新設點 | 121355 + 捷運人流 + 出入口 + 公車站 | 資料 | 供給面真實、需求面模擬；北投網格標 `missingData` 排除 |
| 各區缺口排名 | 同上，依行政區彙總 | 資料 → 前端 | 同上，北投顯示「資料缺漏」 |
| 填滿率、清運調度 | **沒有官方資料**，模擬 IoT | 後端 | 模擬資料 |
| 市民回報 → 會勘佐證 | 我們自己收的回報 | 後端 → 前端 | 有回報，未彙整 |
| Demo 開場的民眾聲音 | 「市長你給我聽好了」 | 資料（僅本機） | 未做 |

### 3.2 前端要做的（依資料推出的需求）

- [ ] **數字一定標單位**。KPI 用開放資料時寫「垃圾桶點位 661」，不要寫「661 組」；官方總數另外顯示「806 組（115 年 6 月，環保局）」。
- [ ] **缺資料和沒有垃圾桶要分開**。北投區在開放資料是 0 筆，各區排名和地圖要顯示「開放資料缺漏」，不能顯示成「北投最缺垃圾桶」。
- [ ] **新設點標示為「候選」**。選址還要過設置原則與現場會勘（人行道寬度、出入口、居民意見），畫面上不能寫成「應設置」。
- [ ] **每個畫面角落標資料來源**，點開能看到資料名稱、日期、真實／模擬。前端已讀 `meta.json`，擴充即可。
- [ ] 市府端加「會勘佐證」視角：選一個里或一個網格，列出這裡的回報數、類型、時間分布、人流量。

### 3.3 後端要做的

- [ ] 回報資料要存得住：`id、kind、lat、lng、binId?、createdAt`，後續要能**依里、行政區、網格彙總**，並可以匯出 CSV 給會勘使用。
- [ ] 新增彙總端點（建議）：
  - `GET /api/reports/summary?by=district|grid` → `[{ key, full, missing, need, total, lastAt }]`
- [ ] 不要宣稱「已通知清潔隊」。現行的滿溢通報走 1999 與環保局管道，我們的回報是補充資料，畫面文案要誠實。
- [ ] 填滿率是模擬的 IoT 資料，API 回應要帶 `"simulated": true`，前端據此標示。

### 3.4 資料組要做的

- [x] 121355 已放進 `data/open/121355-pedestrian-bins.csv`（原檔 BIG5，已轉 UTF-8）。`build_bins.py` 會自動修正 2 筆髒資料：1 筆經緯度填反、1 筆經度多一個小數點（`121.513.652`）。要換最新版就放 `data/raw/bins.csv`，優先使用。
- [x] 人潮熱點清潔箱設置處數（130 筆、12 區含北投）放在 `data/open/hotspot-bins-130.csv`，轉成 `hotspots.json`（同名車站跨區合併後 123 個熱點、893 處）。**資料集名稱與編號待補**；單位是「處」，不能和點位、組數相加。前端尚未使用，可做為北投的替代參考或熱點圖層。
- [ ] 下載 145763 → 整理成 `apps/web/public/data/official_counts.json`：`[{ year, month?, count, unit, source }]`，單位依第 0 節標好。
- [ ] 捷運出入口：查詢 ArcGIS Layer 0，存 `data/raw/mrt_exits.json`。
- [ ] 捷運人流：只取最近一個月，彙總成每站每小時進出量，存 `data/raw/mrt_hourly.csv`（不要 commit 原始 OD 檔）。

- [x] **遮掉資料缺漏的行政區（暫時版）**：`data/scripts/areas.py` 用手描的粗略多邊形圈出北投，網格標成 `missingData: true`，排除在缺口熱區、候選新設點與各區排名之外。已用熱點資料驗證：北投 10 個熱點都在範圍內、其他區 0 個誤判；121355 的 661 筆也沒有落在範圍內。

## 4. 下載方式

> 我們的開發環境連不到政府開放資料網站，以下請在自己的電腦上操作。下載後記下**下載日期**，寫進 `data/raw/SOURCES.txt`。

```bash
# 捷運出入口（ArcGIS，直接存成 WGS84 GeoJSON）
curl -o data/raw/mrt_exits.geojson \
  "https://arcgis.tpgos.gov.taipei/arcgis/rest/services/TAIPEI_MAP/LAYER_MRTSTOPLOC/MapServer/0/query?where=1%3D1&outFields=*&outSR=4326&f=geojson"

# 捷運車站
curl -o data/raw/mrt_stations.geojson \
  "https://arcgis.tpgos.gov.taipei/arcgis/rest/services/TAIPEI_MAP/LAYER_MRTSTOPLOC/MapServer/1/query?where=1%3D1&outFields=*&outSR=4326&f=geojson"

# 捷運 OD 月檔索引（內含各月份檔案網址）
curl -L -o data/raw/mrt_od_index.csv \
  "https://data.taipei/api/frontstage/tpeod/dataset/resource.download?rid=eb481f58-1238-4cff-8caa-fa7bb20cb4f4"

# 公車站牌（SHP，壓縮檔）
curl -L -o data/raw/bus_stops_shp.zip \
  "https://data.taipei/api/frontstage/tpeod/dataset/resource.download?rid=dfd68d8e-d3b9-44df-b614-8850c103239f"

# 陳情案件類別（115 年 9 月）
curl -L -o data/raw/petition_11509.csv \
  "https://data.taipei/api/frontstage/tpeod/dataset/resource.download?rid=b57a0fa8-9507-438b-b2e1-676829a72aff"
```

121355 與 145763 請從 data.gov.tw 頁面下載 CSV（網站不允許程式抓取頁面，要手動點下載）。下載網址若有變動，以資料集頁面為準。
